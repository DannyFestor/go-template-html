# Forward-only goose migrations with a hand-rolled sum file

Migrations are forward-only SQL files run by goose (behind a `migrator` adapter), with no down sections: a change that needs undoing ships as a new migration, because down migrations are rarely exercised against real data and locally the schema can simply be recreated with `app migrate fresh`. Since an applied migration must then never change, a committed `migrations/migrations.sum` (a total hash on the first line, then one hash per file, in the shape of Atlas's `atlas.sum`) is regenerated by `go generate` and checked by a test, by CI and by `app migrate up` before it runs, so an edited migration is caught and two branches that each add a migration collide in git instead of merging out of order.

## Considered Options

- **Down migrations with a `rollback` command** (Laravel parity): an untested escape hatch that cannot restore dropped data; local resets are covered by `fresh`.
- **golang-migrate**: SQL only and records just the highest applied version, so a migration merged later with a lower number is silently skipped.
- **Atlas**: provides the sum file natively, but gates Postgres views, functions and extensions behind a paid tier.
- **Atlas CLI only for `migrate hash`/`validate` on the goose directory**: reintroduces Atlas as a tool dependency for about sixty lines of stdlib code.

## Consequences

- goose stores no checksum in its version table, so the sum guards the repository and the binary, not a database already migrated by an older build.
- The test in `migrations/` also rejects `-- +goose Down` sections, and CI rejects modifications to migration files that already exist on `main`.
- goose's default strict ordering stays on; `allow-missing` is never used.
