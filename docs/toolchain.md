# Toolchain

Every tool the repo uses: its version, its role and the pitfalls to know about. The ADRs explain why each tool was chosen. [upgrading.md](upgrading.md) explains how to bump the pinned ones.

## Go

| | |
| --- | --- |
| Version | `go 1.27`, `toolchain go1.27.2` in `go.mod` |
| Role | Compiles the app. Each process is its own `main` under `cmd/` ([ADR-0010](adr/0010-makefile-as-the-command-surface-with-one-binary-per-process.md)). |

- Any Go 1.21 or newer reads the `toolchain` line and downloads that exact version, so the Go you have installed only needs to be recent enough to bootstrap.
- `GOTOOLCHAIN=local` turns that download off, and the build then fails if your local Go is older than the `go` line.

## templ

| | |
| --- | --- |
| Version | `github.com/a-h/templ`, a `tool` directive in the main `go.mod`, so the CLI and the runtime the generated code imports are the same version ([ADR-0003](adr/0003-templ-for-server-rendered-views.md)) |
| Role | Compiles the `.templ` views in `internal/view` into committed `*_templ.go` files (`make generate-templ`, part of `make generate`) and formats them (`make fmt-templ`, part of `make fmt`; `make fmt-check-templ`, part of `make fmt-check`). |

- Only the root module has templ files, so the templ targets ignore `GO_MODULE`.
- `templ fmt` and `templ generate -f` act on their first file argument only and silently skip the rest, so the templ targets run templ once per file in `FILES`.
- templ has no dry run. `make fmt-check-templ` uses `templ fmt -fail`, which formats a file before it fails on it, because `-stdout` reports every file as changed.
- The generated files carry a `Code generated by templ - DO NOT EDIT.` header, so golangci-lint skips them and the agent hooks refuse edits to them. `.gitattributes` marks them `linguist-generated`.
- Only `internal/view` may import templ. Other packages compose a page with `layout.Render(kind, shell, body)`, which needs no templ import ([ADR-0003](adr/0003-templ-for-server-rendered-views.md)).
- go-arch-lint lists templ's root package next to `github.com/a-h/templ/**`, because the glob does not match the module root.
- Views stay free of logic and branch only on view-model fields, so they get no unit tests of their own. Feature tests check the HTML they render with goquery.

## mockgen

| | |
| --- | --- |
| Version | `go.uber.org/mock`, a `tool` directive in the main `go.mod`, so the mockgen CLI and the `gomock` runtime the mocks import are the same version ([ADR-0010](adr/0010-makefile-as-the-command-surface-with-one-binary-per-process.md)) |
| Role | Generates the test doubles for consumer-declared interfaces ([ADR-0002](adr/0002-layered-architecture-with-actions.md)) through `//go:generate go tool mockgen` next to each interface, run by `make generate-go`, part of `make generate`. |

- Consumer interfaces are unexported, so each mock lands in its consumer's package as `mock_<file>_test.go`, which only tests compile. `-mock_names=<interface>=Mock<Interface>` gives it an exported name that black-box `_test` packages can reach.
- Keep one interface per `-source` file, because source mode mocks every interface in the file.
- The mocks carry a `Code generated by MockGen. DO NOT EDIT.` header, so golangci-lint skips them, which also exempts their `reflect` import from depguard, and the agent hooks refuse edits to them. `.gitattributes` marks them `linguist-generated`, and CI's `make drift-check` fails when they are stale.
- depguard keeps `go.uber.org/mock` out of non-test files, like testify.

## Make

| | |
| --- | --- |
| Version | GNU Make 3.81 or newer (macOS ships 3.81) |
| Role | The only command surface. Run `make` to list the targets ([ADR-0010](adr/0010-makefile-as-the-command-surface-with-one-binary-per-process.md)). |

- `make` with no target runs `help`, which prints every target that has a `## description`, grouped under the `##@ Group` headers above it. The parsing lives in `scripts/make-help.awk`. Targets without a `##` comment are internal and stay hidden.
- `.env` is included if it exists but not exported, so recipes see the same overrides as Compose and the app.
- Composite targets only call other targets, and each leaf target runs one command.
- The Go targets work in the module `GO_MODULE` names, relative to the checkout (`.` by default), and read `FILES` relative to it. `tools/agenthook` is a module of its own, so `lint-agenthook` and `test-agenthook` run `lint` and `test-go` with `GO_MODULE=tools/agenthook`.
- Make 3.81 has no `.ONESHELL` and no `--output-sync`.
- Make 3.81 reads an escaped colon in a prerequisite (`a\:b`) literally, backslash included, so it never matches the target. Target names use hyphens instead of colons.

## Pinned binaries

| | |
| --- | --- |
| Version | `tools/<tool>.version`, with `tools/<tool>.sha256` in `sha256sum` format |
| Role | Tools that aren't Go modules are downloaded into `bin/` by a real Make file target, defined once as the `pinned-binary` macro and implemented by `scripts/install-pinned-binary.sh`. |

- The target detects OS and architecture, downloads with `curl`, refuses to install an asset whose checksum doesn't match, and re-fetches when the version file, the checksum file or the script changes.
- Each binary gets a `bin/<tool>.pin` with the asset URL and its pinned checksum. When Make asks for a binary whose pin still matches, the script only refreshes its timestamp. That is what makes CI's restored `bin/` cache useful, because a checkout leaves the version and checksum files newer than every cached binary.
- Only macOS and Linux on arm64 and x86_64 are supported. Hand-built checksum files list only those, while a verbatim upstream copy such as `tools/vp.sha256` lists every asset. Other platforms fail with "no checksum" or a missing asset.
- Make 3.81 compares timestamps to the second, so a version file edited in the same second as the last download doesn't trigger a re-fetch.

## golangci-lint

| | |
| --- | --- |
| Version | v2.14.0, alone in `tools/golangci-lint.mod` |
| Role | Lints (`make lint`) and formats (`make fmt-go`, `make fmt-check-go`) Go code. Configured in `.golangci.yml` ([ADR-0007](adr/0007-architecture-enforced-by-go-arch-lint-depguard-and-ast-tests.md)). |

- `make lint` and `make lint-wip` pass every test tag (`integration`, `feature`, `e2e`), as `make vet` does. Without them, golangci-lint skips the tagged test files and fails on a directory that holds only those, such as `tests/feature/`.
- It runs through `go tool -modfile=tools/golangci-lint.mod`, so the project toolchain compiles it and it never fails with "built with an older Go". The first run compiles it and is slow.
- `linters.default: all` turns on every linter, including deprecated ones that have a successor. Each disabled linter has its reason next to it.
- By default only one issue is shown per line. `--uniq-by-line=false` shows all of them.
- `run.allow-serial-runners` makes a run wait for another one's lock instead of failing, because the agent hooks lint while other sessions or a human lint too.
- The formatters are gofumpt with its extra rules, goimports with the module path as the local prefix, and golines at 120 columns. `lll` is off because golines wraps long lines.
- The only escape hatch is `//nolint:<linter> // <why>`. nolintlint rejects a directive without a specific linter or a reason.
- gomodguard_v2 blocks every module missing from its allowlist in `.golangci.yml`, so a new dependency needs an entry there as well as in `.go-arch-lint.yml`.
- importas refuses every import alias but one: `internal/job/<area>` is always imported as `<area>job`, because bootstrap wires it next to `internal/action/<area>`, which has the same package name.
- exhaustruct_v5 wants every field of a struct literal, library structs such as `http.Server` included, so unused fields are written out with their zero values.

## go-arch-lint

| | |
| --- | --- |
| Version | v1.19.0, alone in `tools/go-arch-lint.mod` |
| Role | Checks imports between components and confines each third-party library to the components that may use it (`make arch`). Configured in `.go-arch-lint.yml` ([ADR-0007](adr/0007-architecture-enforced-by-go-arch-lint-depguard-and-ast-tests.md)). `make arch-graph` draws the components into `tmp/arch-graph.svg`. |

- It is a whitelist: a Go file outside every component fails the check, and so does a vendor import that no `canUse` allows. The standard library is always allowed, so stdlib bans live in depguard.
- Any warning fails the check. `--max-warnings` only limits how many are printed, and it rejects 0.
- A package that matches several components belongs to the most specific one, so `internal/adapter/postgres` is `adapter-postgres`, not `adapter`.
- A component may not import its own subpackages unless it lists itself in `mayDependOn`. A black-box `_test` package imports the package it tests, so every component with tests lists itself.
- A vendor glob ending in `/**` does not match the module's root package, so a library imported at its root, such as godotenv, is listed by its bare path.
- `ignoreNotFoundComponents` is on, so components can be declared before their packages exist.
- It reads `_test.go` files like any other file, so test-only libraries are allowed everywhere here and kept out of non-test code by depguard. `testdata/` and `node_modules/` directories are excluded, because some npm packages ship Go files, and so is `.claude/worktrees/`, because each agent worktree nested there runs its own check.
- deepScan is off ([ADR-0007](adr/0007-architecture-enforced-by-go-arch-lint-depguard-and-ast-tests.md)). Turning it back on needs a `golang.org/x/tools` newer than the v0.49 go-arch-lint v1.19.0 requires: that version cannot read Go 1.27 export data, and deepScan then silently checks nothing.

| | |
| --- | --- |
| Version | stdlib `go/parser` and `go/ast` |
| Role | Check code shape in `tests/architecture/`: the Action shape, no exported interfaces in `internal/`, no functional options, no `go` statements in the core layers, no variable-time byte comparisons (`bytes.Equal`, `bytes.Compare`, `string(…) ==`) in `internal/`. ## Postgres and migrations

| | |
| --- | --- |
| Version | pgx `github.com/jackc/pgx/v5` and goose `github.com/pressly/goose/v3` in the main `go.mod` ([upgrading.md](upgrading.md#goose)) |
| Role | `internal/adapter/postgres` opens the pgxpool. `internal/adapter/goose` runs the forward-only SQL migrations in `migrations/` ([ADR-0005](adr/0005-forward-only-goose-migrations-with-sum-file.md)). `cmd/migrate up` and `cmd/migrate status` are the only migration commands. |

- The `DB_` values build the connection. `DB_HOST`, `DB_USER`, `DB_PASSWORD` and `DB_NAME` have no default. `DB_SCHEMA` (default `public`) becomes every session's `search_path`, so migrations and queries use unqualified names, and goose keeps its `goose_db_version` table there.
- `statement_timeout` (`WEB_DB_STATEMENT_TIMEOUT`, web only) and `idle_in_transaction_session_timeout` (`DB_IDLE_IN_TRANSACTION_TIMEOUT`) go to Postgres as startup parameters through `RuntimeParams`, never in the DSN. Behind PgBouncer, list both in its `ignore_startup_parameters`. `cmd/migrate` sends neither, so a long migration is never cut off.
- `postgres.Transactor` carries the transaction in `ctx`, and a `WithinTransaction` nested in another one's callback joins its transaction, so the outermost call alone commits or rolls back. Queries and nested calls reach the transaction only through the `ctx` the callback receives: passed the outer `ctx`, a query runs outside the transaction and a nested call opens one of its own ([ADR-0002](adr/0002-layered-architecture-with-actions.md)).
- The pool connects lazily, so `cmd/web` starts while Postgres is down. `/readyz` answers 503 until a ping to Postgres and Valkey succeeds. Its result is cached for `READINESS_CACHE_TTL` (default `5s`), and concurrent requests share one ping, so request rate can't drive more than one ping per TTL. Each ping times out after 2 seconds. `/readyz`, like `/healthz`, is logged at `debug`.
- `make migrate` runs `cmd/migrate up`. It first checks the embedded migrations against the embedded `migrations.sum`, creates `DB_SCHEMA` if it is missing, then applies the pending migrations under goose's Postgres session lock, so two releases migrating at once can't apply one twice. `make migrate-status` lists each migration as `applied` with its time, or `pending`. `make dev` migrates after starting the services.
- `make migrate-create NAME=<snake_case>` writes `migrations/<next number>_<NAME>.sql` with only a `-- +goose Up` line, then refreshes `migrations.sum`. Numbers are five digits and follow the highest one present.
- `make migrate-fresh` drops `DB_SCHEMA` with all its data through `docker compose exec postgres psql`, recreates it and migrates. It only reaches the Compose Postgres, so it can't run in production.
- `migrations/migrations.sum` has the shape of Atlas's `atlas.sum`: a total hash, then one hash per `.sql` file. `internal/migrationsum` computes and verifies it, and `//go:generate` in `migrations/embed.go` rewrites it, through `make generate` or `make generate-migrations-sum`. A test in `migrations/` fails when it is stale or a migration has a `-- +goose Down` section. Two branches that each add a migration conflict on its first line.
- goose stores no checksum, so the sum guards the repo and the binary, not a database an older build already migrated. CI's `make migrations-unchanged` fails when a migration that is already on `origin/main` was modified, renamed or deleted.
- `users.email` is `citext`, whose extension the `users` migration enables, so uniqueness ignores case while the address is stored as typed. `postgres.UserStore.Create` returns `domain.ErrEmailTaken` for a taken address, and `FindByEmail` finds an address in any case.
- `remember_tokens` references `users` with `ON DELETE CASCADE`. `postgres.RememberTokenStore.Consume` locks the row matching the selector, the validator's digest and an expiry after `now`, and stamps its `replaced_at` on first use. A use within the store's replay window after that stamp reports a replay, so a request racing the first one waits for its lock and then sees the stamp. After the window, the token no longer matches.
- `migrations/00001_create_public_schema.sql` holds only `CREATE SCHEMA IF NOT EXISTS public`. It exists because `//go:embed *.sql` doesn't compile without a match, and goose refuses an empty set. The first real migration follows it.

## sqlc

| | |
| --- | --- |
| Version | v1.31.1, in `tools/tools.mod` ([upgrading.md](upgrading.md#sqlc)) |
| Role | Generates typed pgx/v5 code from the queries in `queries/` against the schema in `migrations/` into `internal/adapter/postgres/internal/sqlcgen` (`make generate-sqlc`, part of `make generate`). Configured in `sqlc.yaml` ([ADR-0006](adr/0006-sqlc-data-access-with-opaque-string-ids.md)). |

- It reads the goose migrations as its schema and skips their annotations, so the schema has no copy of its own.
- `sqlc.yaml` maps `uuid` to the standard library's `uuid.UUID` and `timestamptz` to `time.Time`, each nullable one to a pointer in the object form.
- It infers a parameter compared with a nullable column as nullable. Casting it, as in `sqlc.arg(now)::timestamptz`, makes it a plain value.
- It doesn't know the multi-argument `unnest(a, b)` and mangles a `@name::type` cast that an operator follows. Single-argument `unnest` calls side by side and `sqlc.arg(name)::type` work.
- Its parser is cgo, so the first `go tool` run compiles it for about a minute.
- The generated files carry a `Code generated by sqlc. DO NOT EDIT.` header, so golangci-lint skips them and the agent hooks refuse edits to them. `.gitattributes` marks them `linguist-generated`, and CI's `make drift-check` fails when they are stale. Go's `internal` rule keeps the row types inside `internal/adapter/postgres`, whose stores map them to `domain` types.

## Job queue and worker

| | |
| --- | --- |
| Version | Our own code: `internal/worker` and `postgres.JobQueue` ([ADR-0012](adr/0012-hand-rolled-postgres-job-queue-with-leased-at-least-once-delivery.md)) |
| Role | `cmd/worker` performs the jobs in the `jobs` table. `make dev` runs it under air as `watch-worker`, and the production image ships it as `/app/worker`. |

- A job is a struct with `Kind() string`, stored as JSON. Actions enqueue it through an interface they declare with `Enqueue(ctx context.Context, job interface{ Kind() string }) error`, which `postgres.JobQueue` implements. Enqueue joins the transaction in `ctx`, so a job enqueued in a rolled-back transaction never exists.
- Bootstrap registers each handler with `worker.Register(registry, handler, settings)`. `worker.DefaultSettings()` holds a 5 minute lease, 10 retries and the `attempt⁴ + 15s + jitter` backoff of `worker.PolynomialBackoff`, and any of them can be changed per kind. A worker only claims the kinds it registered.
- Every `QUEUE_POLL_INTERVAL` (default `1s`) the worker first makes the jobs whose lease ran out available again and schedules the periodic jobs, then claims due jobs with `FOR UPDATE SKIP LOCKED` until all `QUEUE_CONCURRENCY` (default `10`) goroutines are busy. A job's `ctx` ends with its lease, so a job that outlasts it is cancelled and retried. A rescued job may run twice, so every handler has to tolerate that. One whose lease ran out on its last attempt becomes a failed job without running again.
- A completed job is deleted. A failing job is retried until it has used its retries, then kept as `state = 'failed'` with its `last_error` and `failed_at`, and reported through the error reporter. A panicking handler counts as failing. Outcomes only apply to the attempt that claimed the job, so a worker whose lease was rescued can't touch the job's next attempt.
- `worker.RegisterPeriodic(registry, handler, settings, interval)` registers a periodic job, which runs with its zero value as args. On every poll, each worker inserts the run at the next interval boundary, a multiple of the interval since Go's zero time in UTC, so a daily job runs at midnight UTC and an hourly one on the hour. The unique `(kind, scheduled_for)` drops the other workers' inserts of the same run, so every worker schedules without a leader. The run goes in ahead of its time because a completed job is deleted: inserting the current boundary would run it again after it finished. A worker whose clock lags, or whose insert lands only after another worker finished that run, can still schedule it a second time, which at-least-once delivery already asks handlers to tolerate. A worker that starts mid-interval first runs the job at the next boundary.
- `PruneFailedJobs` (`internal/job/queue`, kind `prune_failed_jobs`) and `PruneExpiredRememberTokens` (`internal/job/auth`, kind `prune_expired_remember_tokens`) are periodic and run daily at midnight UTC. The first deletes the failed jobs whose `failed_at` is more than `QUEUE_FAILED_RETENTION` (default `168h`) ago, the second the remember tokens that have expired or were replaced longer ago than the replay window.
- The runtime and the adapter take the time from the injected clock, never from `now()`, so tests decide what is due.
- On SIGINT or SIGTERM the worker stops claiming and gives running jobs `SHUTDOWN_TIMEOUT` (default `15s`) to finish. It then cancels their `ctx`, waits for them to return, puts them back without using up an attempt and exits with an error. A handler that ignores its `ctx` holds up the exit until a second signal kills the process. A claim in flight at the signal still completes, so its job runs rather than sitting leased.
- `WORKER_DB_MAX_CONNS` (default `12`) sizes the worker's pool, which has no `statement_timeout` because the lease bounds a job. Startup fails when it is below `QUEUE_CONCURRENCY + 2`.
- Feature and e2e tests call `RunQueuedJobs(t)` on the app from `testapp.New`, which runs every due job synchronously on the test's database.

## Mail

| | |
| --- | --- |
| Version | stdlib `net/smtp`, `mime/multipart`, `mime/quotedprintable` and `text/template`, with templ for the HTML part |
| Role | `mailjob.Mailer[M]` (`internal/job/mail`) renders a typed mail and queues it as a `SendMail` job (kind `send_mail`). The worker sends it through `smtp.Sender` (`internal/adapter/smtp`), which points at the Compose Mailpit in dev. |

- An action sends a mail through an interface it declares with `Send(ctx context.Context, mail M) error`, where `M` is the typed mail. Bootstrap is to wire one `mailjob.NewMailer(compose, jobQueue)` per mail type (none ships yet: the verification and reset mails arrive with their flows), whose `compose` maps the mail to a `mailjob.Content`: recipient, subject, a templ component for the HTML part and one for the text part.
- The mail is rendered when it is queued, so the job's payload is the finished message (`domain.MailMessage`: to, subject, HTML, text) and the TTL of a signed URL in it starts at send time. The enqueue joins the transaction in `ctx`, like every job.
- HTML parts wrap their body in `mail.Layout(subject, body)` from `internal/view/mail`. Text parts are stdlib `text/template`s, turned into a component by `mail.Text(template, model)`, so they are not HTML-escaped.
- The message is `multipart/alternative`, text part first, both parts UTF-8 and quoted-printable. The From name is `APP_NAME` and the From address `MAIL_FROM_ADDRESS` (default `hello@example.com`). The subject and From name are Q-encoded, and the `Date` header comes from the clock.
- The `MAIL_` values build the sender: `MAIL_HOST` (default `localhost`), `MAIL_PORT` (default `1025`), `MAIL_USERNAME` and `MAIL_PASSWORD` (default none, which skips `AUTH`) and `MAIL_ENCRYPTION`: `none` (default), `starttls`, which fails when the server offers no STARTTLS rather than sending in plaintext, or `tls` for implicit TLS. `AUTH PLAIN` needs TLS unless the host is `localhost`.
- `net/smtp` takes no `ctx`, so the sender closes the connection when the job's `ctx` ends, at shutdown or when the lease runs out.
- Delivery is at-least-once like every job, so a mail whose job is rescued may arrive twice.
- `testapp.New` gives the worker a `testapp.Outbox` instead of the SMTP sender, so feature and e2e tests read the sent messages from `Outbox.Sent()` after `RunQueuedJobs(t)`.

## Valkey, sessions and request security

| | |
| --- | --- |
| Version | go-redis `github.com/redis/go-redis/v9` in the main `go.mod` ([upgrading.md](upgrading.md#go-redis)) |
| Role | `internal/adapter/valkey` opens the one go-redis client and holds the session store and the rate limiter. The session middleware, its facade and the other request-security middleware live in `internal/middleware` ([ADR-0008](adr/0008-stdlib-built-security-primitives-on-hkdf-derived-keys.md)). |

- The `VALKEY_` values build the client. `VALKEY_HOST` has no default, `VALKEY_PORT` defaults to `6379` and `VALKEY_PASSWORD` to none. `VALKEY_KEY_PREFIX` (default `go-template-html:`) goes in front of every key, followed by its area, such as `session:` or `ratelimit:`, so several apps can share one Valkey. The client connects lazily, so `cmd/web` starts while Valkey is down.
- Only `internal/adapter/valkey` imports go-redis. go-arch-lint lists its root package next to `github.com/redis/go-redis/v9/**`, because the glob does not match the module root.
- A session's token comes from `crypto/rand.Text` and travels in the cookie. Valkey stores the session under the token's SHA-256, so a key read out of Valkey can't be replayed as a cookie. The value is the JSON of one typed struct, whose fields all live in `internal/middleware/session_data.go`.
- A session is written only when a request changed it. Loading it with `GETEX` restarts its idle lifetime (`SESSION_IDLE_LIFETIME`, default `2h`), so a session in use needs no write to stay alive. Its absolute deadline (`SESSION_ABSOLUTE_LIFETIME`, default `24h`) is stored in the struct and set whenever a new token is minted. Concurrent requests are last-write-wins.
- Handlers reach the session through `middleware.Session`, behind interfaces they declare themselves. `SignIn` stores the user ID and credential fingerprint under a new token, `SignOut` deletes the session and clears the cookie, `CurrentUserID` and `CredentialFingerprint` read them, `SetFlash` and `TakeFlash` carry the flash, `SetIntendedURL` and `TakeIntendedURL` carry the intended URL, and `ConfirmPassword` stores when the password was last confirmed under a new token, which `PasswordConfirmedAt` reads. A request that never writes the session gets no cookie and costs no Valkey write.
- Handlers sign a user in through `middleware.Authenticator.SignIn`, directly as registration does or through `authhandler.Sessions.SignIn`, which also issues the remember cookie, as login does. `SignIn` stores the hex HMAC-SHA256 of the user's password hash, on the `credential-fingerprint` subkey, as the credential fingerprint (`internal/adapter/fingerprint`). `Authenticator.Require` is the `auth` middleware: it loads the session's user and hands it on, where `middleware.AuthenticatedUser{}.CurrentUser(ctx)` reads it and the app layout's user menu shows it. A guest is redirected to `/login`, and a session whose user is gone or whose fingerprint no longer matches the stored password hash is signed out first. `Authenticator.RequireGuest` is the `guest` middleware, which sends a signed-in user to `/dashboard`.
- A guest's `GET` to an `auth` route stores its path and query in the session as the intended URL. After login, `Authenticator.Intended` takes it once and falls back to `/dashboard` when there is none, or when it doesn't start with `/` or starts with `//`.
- `POST /login` checks the password with `auth.Login`, which verifies an unknown email against a decoy hash, so the response time doesn't tell whether an account exists. Wrong credentials re-render the form with one alert and no field error. `RATE_LIMIT_LOGIN` (default `5/1m`) counts attempts per lowercased email and client IP, and a successful login clears that count through `RateLimit.Clear`, which fails closed like `Hit`. `POST /logout` sits behind `auth` and redirects to `/`.
- `middleware.PasswordConfirmation.Require` is the `RequirePasswordConfirmation` middleware. Bootstrap's `requirePasswordConfirmation` wraps a route in `auth` first, then sends a user who hasn't confirmed their password within `PASSWORD_CONFIRMATION_TIMEOUT` (default `3h`) to `/confirm-password`, storing a `GET`'s path and query as the intended URL as `auth` does. `POST /confirm-password` sits behind `auth`, checks the password with `auth.ConfirmPassword`, records the confirmation and redirects to the intended URL, with the same fallback as login. A wrong password re-renders the form with a field error. `RATE_LIMIT_PASSWORD_CONFIRMATION` (default `5/1m`) counts attempts per user ID. No route requires the confirmation yet, so the feature tests reach it through a probe route.
- Remember me is a `remember_tokens` row per device: a selector and the SHA-256 of a validator, both drawn from `crypto/rand.Text` by `remembertoken.Generator`, valid for `REMEMBER_LIFETIME` (default `720h`). The `remember` cookie carries `selector.validator`, follows the session cookie's rules and adds a `Max-Age` of the lifetime. `authhandler.Sessions.RestoreRemembered` wraps the `auth` and `guest` route groups: a request without a signed-in user but with a remember cookie consumes its row and issues the device a fresh one in one transaction, then signs the user in under a new session token and rotates the cookie. Another request presenting the same token within the 30-second replay window, as parallel requests after the session expired do, signs the user in too but leaves the cookie alone, so the rotated cookie survives. A cookie whose token is unknown, expired, forged or replaced longer ago than the window is cleared. Logout deletes the device's row and clears the cookie, and the periodic job below deletes expired rows and replaced rows past the window.
- The cookie is `session`, `HttpOnly`, `SameSite=Lax`, `Path=/`, with no `Domain` and no `Max-Age`, so it ends with the browser session. When `APP_URL` is https it is `__Host-session` and `Secure`.
- A cookie whose session is gone or past its absolute deadline makes the request delete what is left of the session and clear the cookie.
- The session is saved on the response's first byte, flush, header or hijack, because the cookie can't be set later. If loading or saving fails, the request gets the reported 500 page in place of its response. The writer wrapper keeps `Flush`, `Hijack` and `Unwrap`.
- `Responder.RedirectWithStatus` sets the flash and redirects. The next full page takes it into `Shell.Status`, and each layout renders it with `component.Status` as the first child of its `<main>`, so boosted navigation shows it too. Partial responses leave it for the next full page.
- The rate limiter counts attempts in a fixed window per key. One `MULTI` runs `SET key 0 NX PX <window>`, `INCR` and `PTTL`, so the window starts with its first attempt, refused attempts don't extend it, and no counter is left without an expiry. Up to twice the limit can pass across a window edge. A handler holds one `web.RateLimit` per limit, whose `web.Limit` names it, so flows keyed by the same value count apart. `Hit` returns nil, the 429 `StatusError` with the wait until the window ends, or, when Valkey can't count, a reported 503: the limiter fails closed. `Responder.RateLimited` re-renders a form with the 429 and `Retry-After`, and hands any other error back for its error page. Each flow's limit is one `RATE_LIMIT_<FLOW>` setting of attempts per window, such as `RATE_LIMIT_REGISTRATION=5/1m` (the default), which counts every registration attempt per client IP.
- `http.CrossOriginProtection` rejects cross-origin requests with an unsafe method, such as `POST`, `PUT`, `PATCH` or `DELETE`, by `Sec-Fetch-Site` or by comparing `Origin` with `Host`, with the 403 page. `CSRF_TRUSTED_ORIGINS` (comma-separated, default none) lists origins to let through, for proxies that rewrite `Host`. There's no synchronizer token.
- The client IP is `RemoteAddr`. When the peer is in `TRUSTED_PROXIES` (comma-separated CIDRs, default none), it is the rightmost `X-Forwarded-For` entry outside them. `middleware.ClientIPFrom(ctx)` reads it.
- Every response carries a strict `Content-Security-Policy` (`script-src 'self'`, `style-src 'self'`, no inline code), `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `Cross-Origin-Opener-Policy: same-origin` and a `Permissions-Policy` that turns off camera, microphone, geolocation, payment and USB. `Strict-Transport-Security: max-age=31536000` is added only when `APP_URL` is https, without `includeSubDomains` or `preload`, so the template commits no other subdomain. htmx 4 adds its indicator CSS as a constructable stylesheet, which `style-src 'self'` doesn't block, so its config stays as it is.

## Password hashing

| | |
| --- | --- |
| Version | `golang.org/x/crypto` in the main `go.mod` ([upgrading.md](upgrading.md#xcrypto)) |
| Role | `internal/adapter/argon2id` hashes and verifies passwords with Argon2id from `golang.org/x/crypto/argon2`, the only password hasher shipped ([ADR-0008](adr/0008-stdlib-built-security-primitives-on-hkdf-derived-keys.md)). Actions reach it behind interfaces they declare themselves. |

- `PASSWORD_HASH_MEMORY_KIB` (default `19456`, 19 MiB), `PASSWORD_HASH_ITERATIONS` (default `2`) and `PASSWORD_HASH_PARALLELISM` (default `1`) are OWASP's Argon2id minimum.
- A hash is a PHC string, `$argon2id$v=19$m=19456,t=2,p=1$<salt>$<key>`, with a 16-byte salt from `crypto/rand` and a 32-byte key, both in unpadded base64, as the Argon2 reference implementation writes them.
- `Verify` derives with the memory, iterations and parallelism stored in the hash, so hashes made before a parameter change keep verifying. It compares in constant time. A value that isn't an Argon2id v19 PHC string with a 32-byte key and non-zero iterations and parallelism is an error rather than a mismatch.
- `NewHasher` refuses zero iterations or parallelism, which `argon2` would panic on.
- `NeedsRehash` reports a hash whose parameters differ from the configured ones, or that isn't a usable Argon2id hash. Login then stores a new hash of the password it just verified. The new hash changes the credential fingerprint, so after a parameter change the user's other sessions are signed out once.
- Only `internal/adapter/argon2id` imports `golang.org/x/crypto/argon2`.

## App key, encryption and signed URLs

| | |
| --- | --- |
| Version | stdlib `crypto/hkdf`, `crypto/aes`, `crypto/cipher` and `crypto/hmac` |
| Role | `internal/adapter/appkey` derives one subkey per purpose from `APP_KEY`. `internal/adapter/aesgcm` encrypts on a subkey, and `internal/adapter/signedurl` signs and verifies URLs on one ([ADR-0008](adr/0008-stdlib-built-security-primitives-on-hkdf-derived-keys.md)). |

- `APP_KEY` is 32 random bytes in standard base64, such as the output of `openssl rand -base64 32`. It has no default, and a missing or malformed key stops the app from booting. The config holds it as a `Secret`, so it never shows up in logs or errors.
- `appkey.Key.Subkey` runs HKDF-SHA256 over the key with the purpose as its info label: `totp-secret`, `recovery-code`, `recovery-code-digest`, `signed-url` or `credential-fingerprint`. Renaming a label invalidates everything encrypted, signed or digested under it.
- `aesgcm.Encrypter` seals with AES-256-GCM and a random 96-bit nonce, which it puts in front of the ciphertext. `Decrypt` returns `aesgcm.ErrUndecryptable` for a ciphertext that was tampered with, truncated or sealed under another key.
- `signedurl.Signer` builds URLs on `APP_URL`. `Sign(path, query)` never expires, `SignTemporary(path, query)` expires after `SIGNED_URL_TTL` (default `2h`) and `SignTemporaryFor(path, query, ttl)` after `ttl`. A temporary URL carries its Unix expiry in `expires`. The `signature` parameter is the hex HMAC-SHA256 of the URL's path, including any path in `APP_URL`, then `?` and the query without `signature`, encoded with its keys sorted, so the host and the order of the parameters don't matter.
- `signedurl.Verifier.Verify(url)` returns `signedurl.ErrInvalidSignature` for a missing or wrong signature, and `signedurl.ErrExpired` once the clock reaches `expires`. It compares with `hmac.Equal`.

## TOTP and recovery codes

| | |
| --- | --- |
| Version | stdlib `crypto/hmac`, `crypto/sha1`, `crypto/sha256` and `crypto/rand` |
| Role | `internal/adapter/totp` generates and checks two-factor authentication codes, `internal/adapter/recoverycode` generates recovery codes and `internal/adapter/hmacdigest` digests them. `postgres.TwoFactorSecretStore` and `postgres.RecoveryCodeStore` keep both encrypted ([ADR-0008](adr/0008-stdlib-built-security-primitives-on-hkdf-derived-keys.md)). |

- A code is RFC 6238 TOTP: HMAC-SHA1, 6 digits, 30-second steps, tested against the RFC's SHA1 vectors. `totp.NewSecret` draws 160 random bits, and `totp.URI` builds the `otpauth://totp/` URI with the secret in unpadded base32.
- `totp.Authenticator.Match(secret, code)` accepts the code of the clock's step or one step either side, compared in constant time, and returns the step it matched.
- `TwoFactorSecretStore.UseStep(user, step)` is the replay guard: `UPDATE … SET last_used_step = step WHERE user_id = … AND last_used_step < step` checks and records in one statement, so a code passes at most once and no earlier step passes after a later one. `Save` replaces the secret and forgets the used steps.
- `recoverycode.NewSet` returns 8 codes shaped `XXXXXXXXXX-XXXXXXXXXX`, each 20 characters of `crypto/rand.Text`'s base32 alphabet.
- `recovery_codes` holds one row per code: the code encrypted, so settings can show it again, and its HMAC-SHA256 digest. `RecoveryCodeStore.Consume` deletes the row matching the digest and reports whether there was one, so a code works once.
- The stores take the `aesgcm.Encrypter` and `hmacdigest.Digester` as interfaces. Bootstrap builds them on the `totp-secret`, `recovery-code` and `recovery-code-digest` subkeys once a flow uses the stores.
- Both tables reference `users` with `ON DELETE CASCADE`, so deleting a user deletes its secret and recovery codes.

## Response compression

| | |
| --- | --- |
| Version | gzhttp from `github.com/klauspost/compress` and `github.com/vearutop/statigz` in the main `go.mod`, `vite-plugin-compression2` in `package.json` ([upgrading.md](upgrading.md#response-compression)) |
| Role | `internal/adapter/compression` wraps the whole middleware chain in gzhttp. `internal/asset` serves the `.br` and `.gz` files the Vite build writes next to each asset through statigz. |

- gzhttp sends zstd or gzip at the library defaults (zstd `SpeedFastest`, gzip's default level), and zstd wins when the client's preferences tie. It compresses only `text/html`, `text/plain`, `text/css`, `text/javascript`, `application/javascript`, `application/json`, `image/svg+xml` and `application/xml`, and only from 1 KiB on. There's no config toggle.
- `text/event-stream` isn't on the list, so a stream is never buffered. gzhttp keeps `Flush`, `Hijack` and `Unwrap`, so `/ws` and `http.ResponseController` work through it.
- A response that already has a `Content-Encoding`, such as a precompressed asset, or a `Content-Range` goes out untouched.
- `web.SkipCompression(w)` sends a response uncompressed, against BREACH. It sets gzhttp's `No-Gzip-Compression` header, which gzhttp strips before sending. Any response that reveals a server-generated secret calls it. The compression adapter's tests check the header through `web.SkipCompression`, so a replacement library has to pass them too.
- `vite-plugin-compression2` writes a brotli and a gzip sibling of each built file at maximum level, in `make vite-build` and `make watch-vite` alike, skipping `manifest.json` and any file the compression would not shrink. No `.zst` is written: brotli 11 beats zstd for static text, and the plugin's zstd needs Node 22.15 or later.
- statigz picks the smallest sibling the client accepts and falls back to the plain file. It sends `Content-Type: application/javascript` for `.js`, an `ETag` and `Vary: Accept-Encoding`. In production it indexes the embedded build once; in local mode it indexes `internal/asset/dist` on every request, because each rebuild renames the files.

## Vite+

| | |
| --- | --- |
| Version | `tools/vp.version`, a [pinned binary](#pinned-binaries) in `bin/vp`, and the `vite-plus` catalog entry in `pnpm-workspace.yaml` |
| Role | Builds the frontend assets (`make vite-build`, `make watch-vite`), formats with oxfmt (`make fmt-js`, `make fmt-check-js`), lints with oxlint (`make lint-js`), type-checks with `tsc` (`make typecheck-js`) and runs the JS unit tests with Vitest (`make test-js`). In local mode it reads `internal/asset/dist` from disk relative to the working directory, re-reads the manifest on every lookup and sends `no-store`.

That match relies on Vite's default `[name]-[hash]` output names, and on `hashCharacters: "base36"` in `vite.config.ts`, because the default base64 hashes can contain a `-`.
- The app embeds whatever `make vite-build` last wrote, so the feature tests and the production image need it to run first. Without it, `internal/asset/dist` holds only `.gitkeep` and production fails at startup.
- The modulepreload polyfill is off and `assetsInlineLimit` is 0, so the output holds no inline script and no `data:` URI.
- oxlint fails on the `correctness`, `suspicious` and `perf` categories, and on functions over the length, complexity, depth and parameter limits golangci-lint uses for Go.

- Tests import the Vitest API from `vite-plus/test`, not from `vitest`. They run under happy-dom and sit next to the code as `*.test.ts`.

## Agent hooks

| | |
| --- | --- |
| Version | `tools/agenthook`, a Go module of its own, which pins `mvdan.cc/sh/v3` in its `go.mod` |
| Role | Guards and checks a Claude Code agent's edits and shell commands. `.claude/settings.json` calls `make -s agenthook-<event>`, which rebuilds `bin/agenthook` whenever its sources change and pipes the hook JSON through stdin. |

| Event | Rule | Change it in |
| --- | --- | --- |
| Before an edit | Denies edits to generated output and names what regenerates it: a file with a `Code generated … DO NOT EDIT.` header (`make generate`), `internal/asset/dist/` (`make vite-build`), `migrations.sum` (`make generate`), `go.sum` (`go mod tidy`) and `pnpm-lock.yaml` (`bin/vp add` or `remove`) | `internal/editrule/generated.go` |
| Before an edit | Asks before editing a guardrail file: `.golangci.yml`, `.go-arch-lint.yml`, `lefthook.yml`, `tools/agenthook/`, `.claude/settings.json`, `.github/workflows/`, `.github/rulesets/` | `internal/editrule/guardrail.go` |
| Before an edit | Asks before editing `go.mod`, `tools/*.mod` or `package.json`, which can add a dependency | `internal/editrule/guardrail.go` |
| Before an edit | Denies edits to a `migrations/*.sql` file that exists on `origin/main`, and the creation of a new one, which `make migrate-create NAME=…` makes instead. A stub on a branch can be edited freely. | `internal/editrule/migration.go` |
| Before an edit | Comment guard: a comment added to a Go, TS, templ, SQL or shell file is denied with "comments only explain a why the code cannot", and the same comment resubmitted in the session asks the human. Comments already in the file pass, and so do directives (see below). | `internal/comment/languages.go` |
| Before a shell command | Denies shell writes into a checkout, so every change goes through the edit tools and their post-edit checks: redirects, `tee`, `sed -i`, `perl -i`, `cp`, `mv` and `ln` into it, `patch`, `git apply`, and inline interpreter scripts (`-c`, `-e`, heredocs) that call a file-writing API. Writes outside every checkout, as under `$TMPDIR`, pass. | `internal/commandrule/write.go` |
| Before a shell command | Denies `git push` to `main`: a `main`, `HEAD:main` or `refs/heads/main` refspec, `--all`, `--mirror`, or a push without a refspec where `main` is checked out. Other branches pass, `--force-with-lease` included. | `internal/commandrule/push.go` |
| Before a shell command | Asks before `git reset --hard`, `clean -f…`, `checkout -- <path>`, `checkout .`, `restore` without `--staged`, `stash drop`, `stash clear`, `branch -D` and `worktree remove --force` | `internal/commandrule/destructive.go` |
| Before a shell command | Asks before `go get`, `go mod edit -require` or `-tool`, `pnpm add`, `vp add` and `npm install <package>`. `go mod tidy` and frozen installs pass. | `internal/commandrule/dependency.go` |
| After an edit | A `.go` file gets `make fmt-go`, `make vet` (every test tag) and `make lint-wip` (no `unused` or `unparam`, since the caller is often not written yet) in its module. A `.templ` file gets `make fmt-templ` and `make generate-templ` on itself, then `make vet` and `make lint-wip` on its package. A `.ts` file gets `make fmt-js` and `make lint-js`. A `migrations/*.sql` file gets `make fmt-sql` on itself, then `make generate-migrations-sum`. The first failure goes back to the agent. | `internal/check/after_edit.go` |
| End of turn | `make build-packages`, go-arch-lint, `make lint` and `make test-go` on the packages this session edited, per module, a `.templ` file counting as the `_templ.go` generated from it, then `make typecheck-js` and `make test-js` if it touched TypeScript. A failure blocks the turn from ending. The gate is skipped when nothing changed since it last passed, and it lets the turn end after 3 blocks in a row. | `internal/check/end_of_turn.go`, `internal/hook/gate.go` |

- Exempt directives: Go `//go:…`, `//nolint:<linter> // <reason>`, `//name:arg` directives and the generated-code header; TS `// @ts-expect-error`, `/// <reference …>` and `oxlint-disable`, `-line`, `-next-line` or `oxlint-enable` naming at least one rule; SQL `-- name: … :<cmd>` and `-- +goose …`; the shebang and `# shellcheck …`; and a `gitleaks:allow` marker in any language. A bare `oxlint-disable` and every `eslint-` directive count as comments, and oxlint's `unicorn/no-abusive-eslint-disable` holds humans to the same rule.
- The adapter in `internal/claude` is the only one, and the rules in `internal/hook` know nothing about Claude Code. Every decision goes out as Claude Code's JSON with exit status 0, so a non-zero status only means the hook broke. `settings.json` turns any failure into exit 1, which Claude Code reports without blocking, so a `bin/agenthook` that no longer builds cannot block the edit that fixes it.
- Every rule judges the checkout of the edited path, or of the directory a command runs in after its `cd`s and `git -C`s, never the hook's working directory. A linked worktree gets the checks of its own Makefile and module.
- Session state (edited paths, comments already denied, the gate's counters) lives in `$(git rev-parse --git-dir)/agenthook/<session id>.json`, so linked worktrees and parallel sessions never share it. The end-of-turn gate reads this session's state from every worktree of the repository.
- Claude Code runs a subagent's hooks under its parent's session ID, and `.claude/settings.json` gates only `Stop`, which fires for the main agent alone. A session that delegates to subagents therefore shares one state with them: its end-of-turn gate checks every file they edited, in their worktrees too, unfinished work included, while their own turns end without a gate.
- go-arch-lint checks the whole root module and cannot be limited to packages, so the gate runs `make arch-json` and keeps only the warnings on this session's files. Two sessions editing different Go packages in one checkout never fail each other's gate. `typecheck-js` and `test-js` cover the whole frontend, so a session that touched TypeScript also sees another session's TypeScript failures.
- The gate records the edits it let through, after a pass or a release, and stays quiet until they change.
- The comment guard lexes rather than parses, so it works on fragments. A line comment marker inside a word, as in `https://` or `${#x}`, does not start a comment, and templ treats only `"` and `` ` `` as string quotes, because its HTML text is full of apostrophes.
- Shell commands are parsed with `mvdan.cc/sh`, never run. Words expand with the hook's environment plus the variables the script assigns. Of the command substitutions, only `$(pwd)` and `$(git rev-parse --show-toplevel)` resolve. Any other substitution stays unknown, and so does a path or directory built from it, which the rules then pass.
- Interpreter scripts are matched against known file-writing calls, not run. A write the list does not know passes, and a script file such as `python3 x.py` is not read.
- No rule covers hook bypasses or force-pushes: the git hooks, the ruleset and CI cover them.
- The tests are tooling tests: table tests over the shell parser and every rule decision in `internal/`, plus recorded Claude Code hook JSON, kept as `testdata/*.json.tmpl` templates that fill in the paths, replayed through the built binary against throwaway repos whose stub Makefile logs the targets it is asked to run.

| Job | Runs |
| --- | --- |
| `lint` | `make fmt-check`, `lint`, `lint-agenthook`, `lint-js`, `typecheck-js`, `lint-shell` and `arch` |
| `generate` | `make generate`, then `make drift-check`, which fails if that changed a tracked file or created a new one, then `make migrations-unchanged`, which fails if a migration already on `origin/main` was modified, renamed or deleted. It checks out the full history to have `origin/main`. |
| `test` | `make e2e-install` and `make services`, then `make vite-build`, because the feature and e2e tests run the app on the embedded build, then `make test-all` and `make coverage` |
| `vuln` | `make vuln` and `make vuln-agenthook` |
| `image` | `make image`, which builds the [production image](#production-image) without pushing it |
| `pr-title` | `make lint-pr-title`, which runs `cog verify` on the pull request's title |

- `.github/workflows/ci.yaml` runs the first five jobs in parallel on pull requests and on pushes to `main`. A newer run cancels an older one on the same ref.
- `pr-title` has its own workflow, `.github/workflows/pr-title.yml`, which also runs when a pull request is edited. Editing a title re-runs only that check.
- Every job runs on `ubuntu-24.04` with `permissions: contents: read`, a checkout without persisted credentials and a timeout: 10 minutes, 20 for `test` and 5 for `pr-title`.
- Every job calls only Make targets ([ADR-0010](adr/0010-makefile-as-the-command-surface-with-one-binary-per-process.md)), apart from the `pr-title` step that gives `cog` a git identity and the `test` step that writes the output of `make playwright-version` to `$GITHUB_OUTPUT` for the Playwright cache key. Steps that several jobs share are written once as YAML anchors.
- Actions are pinned by full commit SHA, with the version in a trailing comment. Nothing bumps them automatically ([upgrading.md](upgrading.md#github-actions)).
- Go comes from `actions/setup-go`, which reads the `toolchain` line of `go.mod`. Node comes only from `bin/vp` through `make js-install`, so `.node-version` stays its only pin. The `image` job sets up neither, because the Dockerfile's build stage brings both.
- Caches: the Go module and build cache, one per job and keyed on `go.mod`, `go.sum`, `tools/*.sum` and `tools/agenthook/go.sum`, because the jobs build different packages and tools while setup-go's own cache would share one key between them; `bin/`, keyed on `tools/*.version`, the checksum files and `scripts/install-pinned-binary.sh`; the pnpm store, keyed on `pnpm-lock.yaml`; the Playwright driver and browsers, keyed on the playwright-go version that `make playwright-version` prints; and the golangci-lint cache, keyed on `tools/golangci-lint.sum` plus the commit, so a pull request restores the newest one, which includes `main`'s.
- The title reaches `cog` through the `PR_TITLE` environment variable and is never interpolated into the script, so a crafted title cannot run as code. `cog` runs without `--ignore-fixup-commits` or `--ignore-merge-commits`, because the squash merge makes the title the commit on `main`. The job sets a git identity first, because `cog` reads the committer from git config.
- `make drift-check` marks new files as intent-to-add before it diffs, so `git diff` sees them. Run locally, it does that to your untracked files too, so it is meant for a clean checkout like CI's.
- The runner image is pinned to `ubuntu-24.04` rather than `ubuntu-latest`, so GitHub moving `latest` to a new release cannot break CI unannounced ([upgrading.md](upgrading.md#runner-image)).

## GitHub settings

| | |
| --- | --- |
| Version | The `gh` on your `PATH`, 2.57 or newer for `gh auth status --active`. It is not pinned. |
| Role | `make github-setup` creates or updates the `main` ruleset from `.github/rulesets/main.json` and sets the merge settings from `.github/merge-settings.json`, through `gh api`. |

It prints `created`, the top-level fields that changed (such as `rules` or `enforcement`), or `already up to date`. GitHub adds defaults to what it stores, so an existing ruleset is always rewritten, and the report compares GitHub's own view of it from before and after.

## Rename

| | |
| --- | --- |
| Version | The system `sed`, BSD or GNU. Nothing is pinned. |
| Role | `make rename MODULE=<module path> [NAME="<display name>"]` turns a fresh clone of the template into a project of its own, through `scripts/rename.sh`. |

- The template carries four tokens, defined in `scripts/rename.sh`: its module path, its slug (the module path's last segment), the slug's database form and its display name. The sweep replaces them with sed in every tracked text file that holds one, module path first, because the module path contains the slug.
- The slug becomes the last segment of `MODULE` and must match `^[a-z][a-z0-9-]*$`. The database form is the slug with `-` turned into `_`, so Postgres names never need quoting. `NAME` defaults to the slug's words, each capitalised.
- It refuses with `already renamed` once `go.mod`'s module is no longer the template's. The target stays in the Makefile, and that guard makes a second run harmless.

- It only edits the working tree: it never commits, changes a remote or deletes a file. It ends by printing the next steps: `make setup`, `make github-setup` and committing the result.
